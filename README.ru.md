# unifi-fw-updater

CLI-инструмент для обновления прошивок точек доступа UniFi — полностью автоматически или через конфиг-файл.

**[English documentation →](README.md)**

---

## Возможности

- **Авто-режим** — находит все точки с доступными обновлениями, скачивает прошивки с серверов Ubiquiti, раздаёт локально, обновляет по одной. Нужны только три переменных окружения.
- **Ручной режим** — указываешь `firmware.yaml` со своими MAC-адресами и URL прошивок.
- Проверка SHA-256 перед обновлением
- Последовательное обновление с ожиданием (ждёт пока каждое устройство вернётся онлайн)
- Защита от обновления роутеров (`udm`, `udr`, `ugw`, `uxg`) — их нужно обновлять через UI
- Поддержка UniFi OS 4.x API (`/proxy/network/`) и legacy контроллеров
- 110 тестов · 86% покрытие · mypy --strict · ruff

## Поддерживаемые модели (авто-режим)

В авто-режиме прошивки скачиваются автоматически для AC-серии:

| Код модели | Устройство |
|---|---|
| `U7PG2` | UAP-AC-Pro |
| `U7LT` | UAP-AC-Lite |
| `U7HD` | UAP-AC-HD |
| `U7SHD` | UAP-AC-SHD |
| `U7NHD` | UAP-nanoHD |
| `U7MSH` | UAP-AC-Mesh |
| `U7MP` | UAP-AC-Mesh-Pro |
| `U7IW` | UAP-AC-IW |

Другие модели (U6, U7 серии WiFi 6/7) используют встроенный механизм обновления контроллера.

## Требования

- Python 3.11+
- Контроллер UniFi с **локальным admin-аккаунтом** — см. [Создание локального admin](#создание-локального-admin) ниже
- Сетевой доступ с твоей машины до контроллера (одна сеть или VPN)

## Быстрый старт — авто-режим

Установи три переменных окружения и запусти:

```bash
export UNIFI_HOST=https://192.168.1.1
export UNIFI_USER=admin
export UNIFI_PASS=your_password

python -m unifi_fw auto
```

Инструмент сам:
1. Подключится к контроллеру и найдёт точки с доступными обновлениями
2. Покажет план и запросит подтверждение
3. Скачает прошивки с `dl.ui.com`
4. Поднимет временный локальный HTTP-сервер
5. Обновит устройства по одному, дожидаясь пока каждое вернётся онлайн
6. Удалит временные файлы и остановит сервер

Добавь `--yes` чтобы пропустить запрос подтверждения.

## Ручной режим

Сначала узнай MAC-адреса своих устройств:

```bash
python -m unifi_fw inventory
```

Скопируй пример конфига и заполни MAC-адреса из вывода inventory:

```bash
cp firmware.example.yaml firmware.yaml
# отредактируй firmware.yaml
```

Затем:

```bash
# Посмотреть что будет обновлено
python -m unifi_fw plan

# Запустить обновление
python -m unifi_fw upgrade --yes
```

Для поля `firmware_url` нужно самостоятельно раздать файл прошивки:

```bash
# Скачай прошивку с ui.com, затем:
cd ~/Downloads
python3 -m http.server 8080
```

Используй `http://ТВОЙ_IP:8080/имяфайла.bin` как URL в `firmware.yaml`.

## Все команды

```
python -m unifi_fw auto        # полностью автоматически, без конфиг-файла
python -m unifi_fw inventory   # список всех устройств
python -m unifi_fw health      # проверка подключения к контроллеру
python -m unifi_fw plan        # план обновлений (нужен firmware.yaml)
python -m unifi_fw upgrade     # запуск обновлений (нужен firmware.yaml)
```

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `UNIFI_HOST` | ✅ | — | URL контроллера, напр. `https://192.168.1.1` |
| `UNIFI_USER` | ✅ | — | Имя локального admin |
| `UNIFI_PASS` | ✅ | — | Пароль |
| `UNIFI_SITE` | — | `default` | Имя сайта |
| `UNIFI_VERIFY_TLS` | — | `false` | Поставь `true` чтобы проверять TLS-сертификат |
| `UNIFI_NETWORK_PREFIX` | — | `/proxy/network` | Префикс API для UniFi OS 4.x. Пустая строка для legacy контроллеров |

**Загрузка из файла** — инструмент не читает `.env` автоматически. Скопируй пример и подгрузи вручную:

```bash
cp .env.example .env
# заполни своими значениями, затем:
set -a && source .env && set +a
```

## Безопасность

- Устройства типа `udm`, `udr`, `ugw`, `uxg` **всегда пропускаются** с предупреждением. Их обновление через API небезопасно — используй веб-интерфейс UniFi OS.
- SHA-256 прошивки проверяется до отправки команды обновления.
- Устройства обновляются последовательно. Следующее начинается только после того как предыдущее вернулось онлайн.
- Таймаут обновления — 15 минут на устройство.

## Создание локального admin

Облачные аккаунты (которыми входишь на ui.com) требуют 2FA и не работают здесь — API возвращает HTTP 499.

Нужен **локальный admin**, созданный напрямую на контроллере:

1. Открой UniFi Network в браузере (`https://192.168.1.1`)
2. Перейди в **Settings → Admins & Users → Invite Admin**
3. Выбери **Local Access Only**
4. Задай имя пользователя и пароль
5. Используй их в `UNIFI_USER` / `UNIFI_PASS`

## Устранение проблем

**`Login failed [499]`** — используется облачный аккаунт с 2FA. Создай локальный admin (см. выше).

**`Login failed [400]`** — неверный логин или пароль.

**`Connection error`** — проверь что `UNIFI_HOST` доступен. Инструмент должен быть в одной сети с контроллером (или подключён через VPN).

**Устройство зависло в состоянии `upgrading`** — подожди до 15 минут. Если таймаут — устройство, вероятно, отклонило прошивку (неверная модель/платформа). Проверь что файл прошивки соответствует модели.

**`UNIFI_NETWORK_PREFIX`** — если получаешь 404 на все API запросы и у тебя self-hosted Network Application (не UniFi OS), установи `UNIFI_NETWORK_PREFIX=` (пустая строка).
